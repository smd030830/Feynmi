# Feynmi 제품 백로그

> 문서 버전: v0.6 / 수정일: 2026-10-22
> 기준 문서: [prd.md](prd.md) v0.7

이 문서는 스토리, 스토리포인트, 스프린트 배치만 관리한다. 요구사항, 규칙, 수치는 PRD가 유일한 기준이며, 인수 조건(AC)은 PRD 절 번호를 참조한다. 화면 AC는 [design-system.md](design-system.md) 9장의 절 번호를 함께 참조한다. PRD와 충돌하면 PRD를 따른다.

## 0. 범례와 전제

- **우선순위(MoSCoW)**: M = Must (MVP 필수), S = Should (여유 시), C = Could, W = Won't (MVP 이후)
- **SP**: 스토리포인트 (1, 2, 3, 5, 8). 상대 추정치이며 팀 인원 확정 후 재산정 필요
- **스프린트**: 1주 단위, 1개월 = 스프린트 4개
- **MVP 완료 기준**: PRD 5.1
- 스토리 형식: `FM-번호` / 유저스토리 / 인수 조건(AC)

- Must 합계 약 138 SP. v0.5(약 100 SP)보다 약 38 SP 늘었다(PRD v0.7 범위 확대). 팀 속도가 주당 25 SP 수준이면 1개월 안에 끝나지 않으므로, 팀 인원 확정 후 재산정하고 컷 순서를 정해야 한다 (PRD 10장).

- S3는 판정 품질에 따라 지연될 가능성이 가장 크다. S2 종료 시점에 개념 추출이 안정적이어야 S3에 진입할 수 있다.
- 가치 검증 시점: S3 종료 시 "설명 → 판정 → 결과" 데모가 가능해야 한다.
