은행 송금으로 이해하는 데이터베이스 트랜잭션

1. 트랜잭션과 원자성
트랜잭션은 여러 데이터 변경을 하나의 논리적 작업으로 묶는 단위이다. 예를 들어 A 계좌에서 1만 원을 빼고 B 계좌에 1만 원을 더하는 두 변경은 하나의 송금 작업으로 다룰 수 있다.
원자성은 작업을 구성하는 변경을 전부 반영하거나 전부 취소하는 성질이다. 출금만 반영되고 입금이 실패한 상태로 송금을 완료하면 안 된다. 실패하면 이번 트랜잭션의 변경을 취소한다.
원자성이 각 변경을 반드시 동시에 실행한다는 뜻은 아니다. 여러 단계로 실행하더라도 성공 또는 실패의 결과를 하나로 다룬다는 뜻이다.

2. 일관성과 격리성
일관성은 트랜잭션 전후에 정해진 데이터 규칙을 유지하는 성질이다. 예를 들어 이 자료에서는 송금 수수료가 없고 두 계좌 외의 거래가 없다고 가정한다. 이 조건에서 송금 전후 두 계좌 잔액의 합은 같아야 한다.
격리성은 동시에 실행되는 트랜잭션들이 서로의 중간 변경 때문에 잘못된 결과를 만들지 않도록 다루는 성질이다. 같은 계좌 잔액을 동시에 읽고 수정하면 한 작업의 결과가 덮어써지는 문제가 생길 수 있다.
데이터베이스는 잠금 등의 수단과 격리 수준을 통해 동시 접근을 제어한다. 구체적으로 어떤 중간 상태를 볼 수 있는지는 격리 수준에 따라 달라지므로, 모든 격리 수준의 동작이 같다고 단정하지 않는다.

3. 지속성과 커밋·롤백
지속성은 성공하여 커밋된 변경이 이후 장애가 발생해도 보존되어야 하는 성질이다. 단순히 프로그램의 메모리에서 숫자가 바뀐 것과 저장이 확정된 것은 구별해야 한다.
커밋은 트랜잭션의 변경을 성공한 결과로 확정하는 동작이다. 롤백은 트랜잭션의 변경을 취소하는 동작이다. 송금 도중 입금이 실패하면 출금을 포함한 이번 송금의 변경을 롤백한다.
성공 응답을 받은 뒤 사용자가 새로 조회했을 때 송금 결과를 확인할 수 있어야 한다. 다만 계좌 접근 권한 확인이나 같은 요청의 중복 처리 방지는 별도의 설계도 필요하다. 트랜잭션을 사용한다는 사실만으로 모든 서비스 문제가 해결되는 것은 아니다.

이 문서의 범위
이 자료는 원자성, 일관성, 격리성, 지속성의 기본 의미와 송금 예시를 다룬다. 복제 구성, 장애 복구 알고리즘과 특정 데이터베이스 제품의 격리 수준별 세부 동작은 다루지 않는다.
