프로세스와 스레드 학습 자료

1. 프로세스
프로세스는 실행 중인 프로그램이다. 실행 파일은 저장된 명령과 데이터이고, 프로세스는 그 프로그램을 실행하는 동안 운영체제가 관리하는 실행 단위이다.
각 프로세스는 자신의 주소 공간을 가진다. 한 프로세스의 일반 변수를 다른 프로세스가 직접 읽거나 쓰지는 못한다. 프로세스 사이에 데이터를 전달하려면 운영체제가 제공하는 통신 수단 등을 사용한다.
예를 들어 서로 분리된 두 계산기 프로세스는 각자의 계산 결과를 일반 변수에 보관할 수 있다. 한 계산기의 결과를 바꾼다고 다른 계산기의 변수가 자동으로 바뀌는 것은 아니다.

2. 스레드
스레드는 프로세스 안에서 명령을 실행하는 흐름이다. 하나의 프로세스에는 여러 스레드가 있을 수 있다.
같은 프로세스의 스레드는 코드와 힙 같은 자원을 공유하지만, 각 스레드는 자신의 스택과 실행 위치를 가진다. 공유 자원을 이용해 데이터를 쉽게 주고받을 수 있지만 동시에 같은 값을 바꾸면 문제가 생길 수 있다.
예를 들어 문서 편집기 안에서 화면 입력을 처리하는 흐름과 저장 작업을 처리하는 흐름을 나눌 수 있다. 작업을 나눈다고 언제나 더 빨라지는 것은 아니다.

3. 경쟁 상태와 동기화
경쟁 상태는 여러 실행 흐름이 공유 데이터에 접근하는 순서에 따라 결과가 달라지는 상황이다. 공유 변수의 값을 읽고, 계산하고, 다시 쓰는 여러 단계가 통째로 한 번에 실행된다고 가정하면 안 된다.
공유 값이 0일 때 두 스레드가 각각 1을 더하려 한다고 하자. 둘 다 먼저 0을 읽고 각각 1을 저장하면 최종 값은 2가 아니라 1이 될 수 있다.
임계 구역은 공유 데이터를 보호하기 위해 동시에 실행되지 않도록 관리해야 하는 코드 구간이다. 뮤텍스 같은 동기화 수단을 사용하면 한 시점에 하나의 스레드만 해당 구간을 실행하도록 제한할 수 있다.
동기화는 정확한 결과를 위해 필요하지만 대기 비용도 생긴다. 공유 데이터가 무엇인지와 어느 구간을 보호할지를 함께 판단해야 한다.

이 문서의 범위
이 자료는 프로세스, 스레드, 경쟁 상태와 동기화의 기본 관계를 설명한다. 구체적인 언어 문법, 프로세스 스케줄링 알고리즘과 교착 상태 해결 방법은 다루지 않는다.
