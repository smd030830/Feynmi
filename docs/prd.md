> LLM을 활용한 능동형 메타인지 학습 지원 시스템
> 문서 버전: v0.4 (초안) / 수정일: 2026-10-19

## 1. 개요

### 1.1 제품 한 줄 정의
학습자가 올린 자료를 AI가 분석하고, 학습자가 직접 설명하거나 답하게 하여 이해도를 판단한 뒤, 부족한 부분 중심으로 피드백과 다음 학습 범위를 제공하는 개인 맞춤형 AI 학습 플랫폼.

### 1.2 프로젝트 정보
| 항목 | 내용 |
|---|---|
| 개발 기간 | 1개월 |
| 용도 | 공모전, 졸업작품 |
| 플랫폼 | 반응형 웹 |
| 서비스 언어 | 한국어 전용 |

## 2. 문제 정의와 필요성

### 2.1 문제
1. **이해 여부를 확인하기 어렵다.** 책이나 강의 중심 학습은 정보 전달에는 효과적이지만, 학습자가 실제로 얼마나 이해했는지 확인하기 어렵다. 이해했다고 느끼는 내용에서도 개념 누락이나 오개념이 생긴다.
2. **범용 AI는 학습 환경을 사용자가 직접 만들어야 한다.** ChatGPT, Gemini 등은 학습에 쓸 수 있지만 학습 방식, 질문, 평가 기준을 사용자가 직접 정해야 하고, 일관된 학습 과정과 지속적인 기록 관리가 없다.
3. **이해하지 못한 부분은 사람마다 다르다.** 같은 내용을 학습해도 막히는 지점이 다르므로 학습자의 설명에 근거한 개인별 피드백이 필요하다.

### 2.2 기회
사용자의 답변으로 현재 이해 상태를 판단하고, 부족한 내용만 골라 학습시키며, 결과를 누적 관리하는 학습 환경을 제공한다.

### 2.3 경쟁/대체재 분석

조사일: 2026-10-19. 공식 페이지와 공개 자료 기준이며, 기능과 정책은 수시로 바뀌므로 제출 전 재확인이 필요합니다.

| 구분 | 서비스 | 핵심 강점 | FeynMi와의 차이 |
|---|---|---|---|
| 언어 학습 | **듀오링고** (Duolingo Max) | 게임화된 학습 경험. 상위 구독(Max)에서 생성형 AI 기능 제공: 문제 풀이 후 정오답 이유를 대화로 설명하는 Explain My Answer, AI 캐릭터와 대화 연습하는 Roleplay, 영상통화 연습(Video Call) | 정해진 언어 코스 안에서 동작하며 사용자가 올린 자료를 분석하지 않는다. AI는 "내 답이 맞은 이유/틀린 이유"를 설명해 주는 쪽이고, 학습자가 개념을 풀어 설명하면 평가하는 구조가 아니다. 학습 영역이 언어에 한정 |
| 국내 대학생 AI 학습 앱 | **UnivAI** (univai.co.kr) | 한국어 최적화. PDF, PPT, Word, 유튜브 링크, 강의 녹음, 메모, 필기 사진을 넣으면 요약, 퀴즈, 플래시카드, 마인드맵, AI 튜터를 자동 생성. 웹과 iOS, Android 지원. 공식 페이지는 2026년 9월 기준 누적 가입 55만 명을 내세움 (자체 집계) | 시험 대비용 "생성" 기능(요약, 퀴즈, 암기 카드) 중심. 공식 페이지에서 확인한 범위에서는, 학습자의 설명을 개념 기준과 비교해 이해 상태(이해/부분 이해/오개념)를 판정하고 누적하는 기능은 확인되지 않음 |
| 범용 AI 노트 | **NotebookLM** (Google) | 업로드한 자료에 근거한 답변과 인라인 출처 표시. Studio에서 스터디 가이드, 플래시카드, 퀴즈(문항 수와 난이도 조절 가능), 마인드맵, 오디오/비디오 요약 생성. 대화 스타일을 Learning Guide 등으로 설정 가능. 무료 제공 | 자료 이해를 돕는 요약, 문제 생성이 중심이며 학습 방식은 사용자가 고른다. 확인한 범위에서는 개념별 이해 상태를 누적 관리하는 기능이 확인되지 않음 |

**종합 차별점**
- **설명하는 학습자 / 평가하는 AI**: 경쟁 서비스는 자료를 가공해 "주는" 기능(요약, 퀴즈, 카드)이 강하다. FeynMi는 학습자의 설명을 평가하는 파인만식 흐름이 중심이다.
- **개념 단위 이해 상태 추적**: 이해, 부분 이해, 오개념, 미학습을 개념별로 판정하고 누적하여 취약 개념을 중심으로 다음 학습을 안내한다.
- **단일 흐름**: 별도 프롬프트 없이 자료 분석, 학습, 판정, 피드백이 이어진다.

**유의점**
- UnivAI의 AI 튜터와 NotebookLM의 대화 기능은 질의응답 형태로 쓸 수 있으므로, FeynMi의 차별점은 "AI가 묻고 학습자가 설명하며 상태가 누적된다"는 점에서 분명히 보여주어야 한다.
- 본 조사의 "UnivAI"는 한국 서비스 univai.co.kr이다. 동명의 인도계 교육 기업(Univ.AI)과는 다른 서비스다.

## 3. 제품 목표

- 복잡한 프롬프트 없이 "자료 분석 → 학습 → 답변 → 이해도 판단 → 피드백"이 자연스럽게 이어지는 학습 경험 제공
- 수동적 읽기에서 능동적 설명 중심 학습으로 전환
- 이해한 개념과 부족한 개념을 구분하여 개인 맞춤 피드백 제공
- 학습 결과를 누적 기록하여 지속적인 학습 관리 지원

## 4. 타겟 사용자

### 4.1 우선순위
1순위: **대학생** (전공 수업자료 복습). 자격증/시험 수험생과 중고등학생은 MVP 범위 밖의 확장 대상.

### 4.2 페르소나
**P1. 김민준 (대학교 2학년, 전공 수업 수강)**
- 상황: 강의 PPT와 PDF는 많은데 시험 직전에야 모르는 부분을 알게 됨
- 니즈: 내가 정확히 어디를 모르는지 알고 그 부분만 공부하고 싶음
- 불만: 범용 AI에 매번 "나에게 퀴즈를 내줘"라고 프롬프트를 써야 하고, 지난 학습 결과가 남지 않음

### 4.3 대표 사용 시나리오
1. 민준이 강의 PDF를 업로드한다.
2. AI가 핵심 개념 목록(예: 8개)을 추출하여 보여준다.
3. 민준이 개념을 골라 자기 말로 설명한다.
4. AI가 설명을 평가하고 "이해 / 부분 이해 / 오개념"으로 판정하며, 근거와 함께 빈틈을 짚는 추가 질문을 던진다.
5. 대화가 끝나면 개념별 이해 상태와 피드백 요약이 저장된다.
6. 다음에 접속하면 홈 화면에서 취약 개념과 다음 학습 추천을 본다.

## 5. 범위

### 5.1 MVP 포함 (In Scope)
| 기능 | MVP 수준 |
|---|---|
| F1 학습자료 입력/분석 | **PDF, PPTX** 업로드, 텍스트 추출, 핵심 개념 목록 자동 생성 (편집 기능 없음) |
| F2 답변 기반 이해도 판단 | 개념 선택 → 학습자 설명 → 4단계 상태 판정 + 근거, 추가 질문 후 재답변 (개념당 최대 2회) |
| F3 맞춤형 피드백/학습 | 4파트 피드백(맞은/빠진/잘못된 부분/보완), 취약 개념 기반 다음 학습 안내 |
| F4 학습 현황/기록 | Firebase 로그인, 계정별 저장, **단순 홈 화면**(자료 목록, 개념별 상태, 취약 개념) |
| F5 AI 학습 엔진 | RAG(청크 임베딩 + Top-k 검색) + **GPT(OpenAI API) 단일 공급자**로 개념 추출, 판정, 피드백 |

> 1개월 개발 기간에 맞춰, "자료 업로드 → 설명 → 판정 → 피드백 → 홈에서 결과 확인" 한 사이클이 끝까지 동작하는 것을 MVP의 완료 기준으로 한다.

### 5.2 MVP 제외 (Out of Scope, 이후 확장)
- 이미지(PNG, JPG) 업로드, 스캔 PDF 처리 (멀티모달 추출)
- 개념 목록 수정/삭제/추가
- 세션 중단 후 이어하기, "모르겠어요" 힌트 기능
- 판정 이의제기, 피드백 👍/👎 평가
- 자료/계정 삭제 기능
- 세션 상세 기록 열람, 개념별 상태 변화 추이
- Gemini 등 다른 LLM 공급자 연동 및 비교
- 사용자별 호출 상한, 호출 로그/비용 모니터링
- 학습 일정 관리, 단계별 학습 추천 고도화
- 객관식/단답 퀴즈 모드
- 영어 등 다국어 자료 및 UI
- 네이티브 모바일 앱
- 교수자/관리자용 기능, 학습자 간 공유
- .ppt(구형 형식) 지원

## 6. 기능 요구사항

### F1. 학습자료 입력 및 분석
- FR-1.1 사용자는 PDF, PPTX 파일을 업로드할 수 있다. (.ppt 미지원, PNG/JPG는 MVP 이후)
- FR-1.2 시스템은 파일에서 텍스트와 구조를 추출한다. 텍스트 추출이 불가능한 스캔 PDF는 지원하지 않음을 안내한다.
- FR-1.3 시스템은 자료에서 핵심 개념 목록과 각 개념의 기준 설명, 채점 체크리스트(핵심/보조 요소 3~5개, 6.1 참조)를 생성한다.
- FR-1.4 사용자는 생성된 개념 목록을 확인할 수 있다. (수정/삭제는 MVP 이후)
- FR-1.5 지원하지 않는 형식, 용량 초과, 추출 실패 시 사유를 안내한다.

### F2. 사용자 답변 기반 이해도 판단
- FR-2.1 사용자는 개념 하나를 선택해 자기 말로 설명할 수 있다 (파인만 기법).
- FR-2.2 AI는 설명을 개념의 채점 체크리스트와 요소별로 비교하고, 전체 상태는 6.1의 규칙으로 산출한다.
- FR-2.3 판정은 아래 4개 상태와 근거 문장(사용자 답변과 자료의 해당 부분)을 함께 제공한다.

| 상태 | 의미 |
|---|---|
| 이해 | 모든 핵심 요소를 충족 |
| 부분 이해 | 일부 핵심 요소가 누락/부분 (답변했으나 맞히지 못한 경우 포함) |
| 오개념 | 핵심 요소와 모순되는 진술 포함 |
| 미학습 | 해당 개념에 아직 답변을 제출하지 않음 |

- FR-2.4 AI는 빈틈을 짚는 추가 질문을 던지고, 사용자의 재답변을 반영해 판정을 갱신한다. 추가 질문은 개념당 최대 2회로 제한한다 [가정].

### F3. 개인 맞춤형 피드백 및 학습
- FR-3.1 시스템은 이미 이해한 내용보다 부족한 개념을 우선하여 피드백한다.
- FR-3.2 피드백은 (a) 맞은 부분, (b) 빠진 부분, (c) 잘못된 부분, (d) 보완 설명으로 구성한다.
- FR-3.3 시스템은 판정 결과에 기반하여 다음 학습 개념을 제안한다.
- (MVP 이후) 사용자는 피드백 유용성을 평가(👍/👎)할 수 있다.

### F4. 학습 현황 및 기록 관리
- FR-4.1 로그인/회원가입은 Firebase Authentication으로 처리하며, 로그인 수단은 이메일/비밀번호와 구글 로그인이다. 백엔드는 클라이언트가 보낸 Firebase ID 토큰을 검증하여 사용자를 식별한다.
- FR-4.2 학습 세션, 답변, 판정 결과를 계정별로 저장한다.
- FR-4.3 홈 화면은 다음 세 가지만 표시한다.
  - 내 자료 목록 (자료별 개념 수와 상태 분포)
  - 개념별 이해 상태
  - 취약 개념 (오개념, 부분 이해). 클릭하면 해당 개념 학습으로 이동하며, 이것이 "다음 학습 안내" 역할을 한다.
- FR-4.4 (MVP 이후) 자료와 학습 기록 삭제, 세션 상세 기록 열람, 상태 변화 추이.

### F5. AI 학습 엔진
- FR-5.1 자료를 청크로 분할, 임베딩하여 pgvector에 저장한다 (RAG).
- FR-5.2 답변 평가 시 관련 청크를 검색해 근거로 사용한다.
- FR-5.3 MVP는 GPT(OpenAI API)만 사용한다(생성과 임베딩 모두). 생성 모델은 GPT-5.6 Luna이며, 모델 ID는 환경변수로 관리한다. 임베딩 모델은 [TBD]. 호출 코드는 별도 모듈로 분리하여 이후 다른 공급자로 교체할 수 있게 한다.
- FR-5.4 판정 결과는 정해진 JSON 스키마로 출력하며, 검증 실패 시 재시도한다.
- FR-5.5 자료에 없는 내용을 사실처럼 단정하지 않는다 (근거 인용, 불확실 시 표시).

### 6.1 이해도 판단 로직 (F2, F5)

LLM이 "이해했는가"를 통째로 판정하지 않는다. **LLM은 요소별 판정만 하고, 전체 상태는 코드가 규칙으로 산출한다.** 같은 입력이면 같은 상태가 나오고, 판정 이유를 요소 단위로 설명할 수 있다.

**① 채점 기준 생성 (자료 분석 시)**
- 개념마다 "이해했다면 반드시 언급해야 할 요소" 3~5개를 만든다.
- 각 요소에는 중요도(**핵심 / 보조**, 2단계, 가중치 없음)와 자료 내 근거 청크 위치를 붙인다.
- 자료에서 드러나는 흔한 오개념이 있으면 0~2개를 함께 기록한다.

**② 답변 평가 (GPT 1회 호출)**
- 입력: 개념의 체크리스트, RAG로 검색한 근거 청크, 해당 개념에 대한 학습자의 **누적 답변 전체**
- 출력(JSON): 요소별 판정(`충족 / 부분 / 누락 / 모순`)과 판정 근거가 된 학습자 문장, 피드백(4파트), 추가 질문 후보
- 판정은 보수적으로 한다. 의심스러우면 한 단계 낮은 판정을 준다.
- 자료 문장을 그대로 옮긴 것으로 보이는 진술은 충족으로 인정하지 않고, 자기 말로 다시 설명하도록 유도한다. 표현이 달라도 의미가 맞으면 충족으로 인정한다.

**③ 전체 상태 산출 (코드 규칙, 위에서부터 순서대로 적용)**

| 순서 | 조건 | 상태 |
|---|---|---|
| 1 | 해당 개념에 제출된 답변이 없음 | 미학습 |
| 2 | 핵심 요소 중 하나 이상이 `모순` | 오개념 |
| 3 | 모든 핵심 요소가 `충족` | 이해 |
| 4 | 그 외 (답변했으나 핵심 요소 일부가 `부분/누락`) | 부분 이해 |

- 보조 요소는 상태에 영향을 주지 않고 피드백에만 반영한다.
- **자료에 없는 내용**은 오개념으로 처리하지 않고 "자료에서 확인되지 않음"으로 표시하며, 상태 산출에서 제외한다.

**④ 추가 질문과 재판정**
- 누락/모순 요소 중 핵심 요소를 우선하여 질문하며, 정답을 직접 알려주지 않는다.
- 개념당 최대 2회. 재답변이 오면 최신 답변만이 아니라 누적 답변 전체를 다시 평가한다.
- 이전 판정은 이력으로 보존한다.

**⑤ 출력 안정성**
- 출력은 JSON 스키마로 검증하고 실패 시 재시도한다.
- 출력 변동을 줄이는 설정을 사용한다. (모델별로 조정 가능한 파라미터가 다르므로 구현 시 확인)

## 7. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 보안/개인정보 | 전송 구간 HTTPS, 인증은 Firebase Authentication 사용, 본인 자료만 접근 가능 (탈퇴/삭제 기능은 MVP 이후) |
| 저작권 | 업로드 자료는 본인 학습용으로만 사용하며 타인에게 공개하지 않는다. 약관에 명시 |
| 외부 API 전송 고지 | 업로드 내용이 외부 LLM API로 전송됨을 가입/업로드 시 고지 |
| 신뢰성 | LLM 호출 실패 시 재시도 및 오류 안내 |
| 호환성 | 최신 Chrome, Safari, Edge. 모바일 브라우저 반응형 |
| 접근성 | 기본 키보드 조작, 색 대비 준수 (권장) |
| 언어 | 한국어 전용 |

## 8. 사용자 흐름

```
로그인(Firebase) → 홈 → 자료 업로드 → 분석 진행 → 개념 목록 확인/수정
→ 개념 선택 → 설명 작성 → AI 판정 + 추가 질문 → 재답변
→ 피드백 요약 → 기록 저장 → 홈(현황 갱신, 다음 학습 추천)
```

## 9. 시스템 구성과 기술

| 영역 | 기술 | 비고 |
|---|---|---|
| 프론트엔드 | Next.js (React 기반) | 반응형 웹 |
| 인증 | Firebase Authentication | 이메일/비밀번호, 구글 로그인. 백엔드에서 ID 토큰 검증 (Firebase Admin SDK) |
| 백엔드 | Python, FastAPI | 비동기 처리에 적합 |
| DB | PostgreSQL + pgvector | 관계형 데이터와 임베딩을 한 곳에 저장 |
| 생성형 AI | GPT-5.6 Luna (OpenAI API) | MVP는 단일 공급자. 모델 ID는 환경변수로 관리. 호출 모듈 분리로 이후 교체 가능 (Gemini 등) |
| 검색 증강 | RAG | 자료 증가와 누적 학습을 대비해 유지 |
| 파일 처리 | PPTX/PDF 텍스트 파서 | 이미지/스캔은 MVP 이후 GPT 멀티모달로 확장 |
| 형상 관리 | Git | |
| CI/CD | GitHub Actions, Docker | |

**RAG 적용 메모**: 자료 한두 개 분량은 긴 컨텍스트로도 처리 가능하지만, 자료가 누적되고 근거 검색 정확도를 높이기 위해 RAG를 유지한다. 구현 초기에 "RAG 유무" 비교 실험으로 효과를 검증할 것을 권장한다.

### 9.1 주요 데이터 엔티티 (개략)
User(Firebase UID 연결), Material, Chunk(embedding), Concept(기준 설명), ConceptElement(핵심/보조 요소, 근거 청크), Session, Message(답변/질문), Assessment(개념별 상태, 시각), AssessmentElement(요소별 판정, 근거 문장), Feedback

| API 비용 급증 | 운영 불가 | 사용자별 호출 상한, 캐싱, 모델 등급 분리 |
| 저작권/개인정보 | 법적 이슈 | 본인 학습용 한정, 약관과 고지, 삭제 기능 |
| 범용 AI, UnivAI, NotebookLM과의 차별성 약화 | 가치 불명확 | 파인만식 설명 평가와 개념 단위 상태 추적을 데모의 중심에 둠 |
