# Feynmi(파인마이) PRD

> LLM을 활용한 능동형 메타인지 학습 지원 시스템
> 문서 버전: v0.7 / 수정일: 2026-10-22

**이 문서는 Feynmi의 단일 진실 공급원(Single Source of Truth)이다.** 기능 요구사항, 판정 규칙, 기술 스택, 수치 기준은 이 문서만 정의한다. 다른 문서(`docs/backlog.md`, `AGENTS.md` 등)는 이 문서의 절 번호를 참조하며 내용을 복제하지 않는다. 충돌 시 이 문서가 우선한다.

---

## 1. 개요

### 1.1 제품 한 줄 정의
학습자가 올린 자료를 AI가 분석하고, 학습자가 직접 설명하거나 답하게 하여 이해도를 판단한 뒤, 부족한 부분 중심으로 피드백과 다음 학습 범위를 제공하는 개인 맞춤형 AI 학습 플랫폼.

### 1.2 프로젝트 정보
| 항목 | 내용 |
|---|---|
| 서비스명 | Feynmi (한글: 파인마이) |
| 개발 기간 | 1개월 |
| 용도 | 공모전, 졸업작품 |
| 플랫폼 | PC 웹 (모바일 레이아웃은 MVP 이후) |
| 서비스 언어 | 한국어 전용 |

## 2. 문제 정의와 필요성

### 2.1 문제
1. **이해 여부를 확인하기 어렵다.** 책이나 강의 중심 학습은 정보 전달에는 효과적이지만, 학습자가 실제로 얼마나 이해했는지 확인하기 어렵다. 이해했다고 느끼는 내용에서도 개념 누락이나 오개념이 생긴다.
2. **범용 AI는 학습 환경을 사용자가 직접 만들어야 한다.** ChatGPT, Gemini 등은 학습에 쓸 수 있지만 학습 방식, 질문, 평가 기준을 사용자가 직접 정해야 하고, 일관된 학습 과정과 지속적인 기록 관리가 없다.
3. **이해하지 못한 부분은 사람마다 다르다.** 같은 내용을 학습해도 막히는 지점이 다르므로 학습자의 설명에 근거한 개인별 피드백이 필요하다.

### 2.2 기회
사용자의 답변으로 현재 이해 상태를 판단하고, 부족한 내용만 골라 학습시키며, 결과를 누적 관리하는 학습 환경을 제공한다.

### 2.3 경쟁/대체재 분석

조사일: 2026-10-19. 공식 페이지와 공개 자료 기준이며, 기능과 정책은 수시로 바뀌므로 제출 전 재확인이 필요합니다.

| 구분 | 서비스 | 핵심 강점 | Feynmi와의 차이 |
|---|---|---|---|
| 언어 학습 | **듀오링고** (Duolingo Max) | 게임화된 학습 경험. 상위 구독(Max)에서 생성형 AI 기능 제공: 문제 풀이 후 정오답 이유를 대화로 설명하는 Explain My Answer, AI 캐릭터와 대화 연습하는 Roleplay, 영상통화 연습(Video Call) | 정해진 언어 코스 안에서 동작하며 사용자가 올린 자료를 분석하지 않는다. AI는 "내 답이 맞은 이유/틀린 이유"를 설명해 주는 쪽이고, 학습자가 개념을 풀어 설명하면 평가하는 구조가 아니다. 학습 영역이 언어에 한정 |
| 국내 대학생 AI 학습 앱 | **UnivAI** (univai.co.kr) | 한국어 최적화. PDF, PPT, Word, 유튜브 링크, 강의 녹음, 메모, 필기 사진을 넣으면 요약, 퀴즈, 플래시카드, 마인드맵, AI 튜터를 자동 생성. 웹과 iOS, Android 지원. 공식 페이지는 2026년 9월 기준 누적 가입 55만 명을 내세움 (자체 집계) | 시험 대비용 "생성" 기능(요약, 퀴즈, 암기 카드) 중심. 공식 페이지에서 확인한 범위에서는, 학습자의 설명을 개념 기준과 비교해 이해 상태(이해/부분 이해/오개념)를 판정하고 누적하는 기능은 확인되지 않음 |
| 범용 AI 노트 | **NotebookLM** (Google) | 업로드한 자료에 근거한 답변과 인라인 출처 표시. Studio에서 스터디 가이드, 플래시카드, 퀴즈(문항 수와 난이도 조절 가능), 마인드맵, 오디오/비디오 요약 생성. 대화 스타일을 Learning Guide 등으로 설정 가능. 무료 제공 | 자료 이해를 돕는 요약, 문제 생성이 중심이며 학습 방식은 사용자가 고른다. 확인한 범위에서는 개념별 이해 상태를 누적 관리하는 기능이 확인되지 않음 |

**종합 차별점**
- **설명하는 학습자 / 평가하는 AI**: 경쟁 서비스는 자료를 가공해 "주는" 기능(요약, 퀴즈, 카드)이 강하다. Feynmi는 학습자의 설명을 평가하는 파인만식 흐름이 중심이다.
- **개념 단위 이해 상태 추적**: 이해, 부분 이해, 오개념, 미학습을 개념별로 판정하고 누적하여 취약 개념을 중심으로 다음 학습을 안내한다.
- **단일 흐름**: 별도 프롬프트 없이 자료 분석, 학습, 판정, 피드백이 이어진다.

**유의점**
- UnivAI의 AI 튜터와 NotebookLM의 대화 기능은 질의응답 형태로 쓸 수 있으므로, Feynmi의 차별점은 "AI가 묻고 학습자가 설명하며 상태가 누적된다"는 점에서 분명히 보여주어야 한다.
- 본 조사의 "UnivAI"는 한국 서비스 univai.co.kr이다. 동명의 인도계 교육 기업(Univ.AI)과는 다른 서비스다.

## 3. 제품 목표

- 복잡한 프롬프트 없이 "자료 분석 → 학습 → 답변 → 이해도 판단 → 피드백"이 자연스럽게 이어지는 학습 경험 제공
- 수동적 읽기에서 능동적 설명 중심 학습으로 전환
- 이해한 개념과 부족한 개념을 구분하여 개인 맞춤 피드백 제공
- 학습 결과를 누적 기록하여 지속적인 학습 관리 지원

## 4. 타겟 사용자

### 4.1 우선순위
1순위: **대학생** (전공 수업자료 복습). 자격증/시험 수험생과 중고등학생은 MVP 범위 밖의 확장 대상.

### 4.2 페르소나
**P1. 김민준 (대학교 2학년, 전공 수업 수강)**
- 상황: 강의 PPT와 PDF는 많은데 시험 직전에야 모르는 부분을 알게 됨
- 니즈: 내가 정확히 어디를 모르는지 알고 그 부분만 공부하고 싶음
- 불만: 범용 AI에 매번 "나에게 퀴즈를 내줘"라고 프롬프트를 써야 하고, 지난 학습 결과가 남지 않음

### 4.3 대표 사용 시나리오
1. 민준이 "운영체제" 프로젝트를 만들고 강의 PDF 여러 개를 업로드한다.
2. AI가 자료마다 핵심 개념 목록(5~10개)을 추출하고, 프로젝트에서 모아서 보여준다.
3. 민준이 개념을 골라 자기 말로 설명한다.
4. AI가 설명을 평가하고 "이해 / 부분 이해 / 오개념"과 이해도 점수로 판정하며, 근거와 함께 빈틈을 짚는 추가 질문을 던진다.
5. 세션이 끝나면 결과 화면에서 4파트 피드백과 점수 변화를 보고, 개념별 상태와 기록이 저장된다.
6. 다음에 접속하면 홈 화면에서 학습 통계, 다음 학습 추천, 취약 개념을 보고, 학습기록에서 지난 세션을 다시 본다.

## 5. 범위

### 5.1 MVP 포함 (In Scope)
| 기능 | MVP 수준 |
|---|---|
| F1 학습자료 입력/분석 | **프로젝트** 생성, 프로젝트별 **PDF, PPTX** 여러 개 업로드, 텍스트 추출, 자료별 핵심 개념 목록 자동 생성 (편집 기능 없음) |
| F2 답변 기반 이해도 판단 | 개념 선택 → 학습자 설명 → 4단계 상태 판정 + **이해도 점수(%)** + 근거, 추가 질문 후 재답변 (개념 세션당 최대 3회) |
| F3 맞춤형 피드백/학습 | 4파트 피드백(맞은/빠진/잘못된 부분/보완), 결과 화면(점수 변화, 다음 학습 추천), 취약 개념 기반 다음 학습 안내 |
| F4 학습 현황/기록 | Firebase 로그인(이메일/비밀번호, 구글) + 닉네임, 계정별 저장, 홈 화면(학습 통계, 다음 학습 추천, 프로젝트 목록, 취약 개념), **학습기록과 세션 상세 열람**, **설정**(계정, 로그인 및 보안, 학습 설정, 회원 탈퇴), 앱 내 알림, 이용약관/개인정보 처리방침 정적 페이지 |
| F5 AI 학습 엔진 | RAG(청크 임베딩 + Top-k 검색) + **OpenAI API 단일 공급자**로 개념 추출, 판정, 피드백 |

> 1개월 개발 기간에 맞춰, "프로젝트 생성 → 자료 업로드 → 설명 → 판정 → 결과 → 홈에서 현황 확인" 한 사이클이 끝까지 동작하는 것을 MVP의 완료 기준으로 한다. 플랫폼은 **PC 브라우저**만 지원한다 (7장).

### 5.2 MVP 제외 (Out of Scope, 이후 확장)
- 이미지(PNG, JPG) 업로드, 스캔 PDF 처리 (멀티모달 추출)
- 개념 목록 수정/삭제/추가
- 세션 중단 후 이어하기, "모르겠어요" 힌트 기능
- 판정 이의제기, 피드백 👍/👎 평가
- 자료·프로젝트 삭제와 수정 기능 (계정 삭제인 회원 탈퇴는 MVP 포함, FR-4.7)
- 개념별 상태·점수 변화 추이 (세션 안의 점수 변화 표시는 MVP 포함, FR-3.5)
- 네이버, 카카오 등 Firebase 기본 제공 외 소셜 로그인, 로그인 계정 연결·해제
- 모바일 브라우저 반응형 레이아웃 (PC 브라우저만 지원)
- 이메일·브라우저 푸시 알림 (앱 내 알림만 MVP 포함, FR-4.8)
- Gemini 등 다른 LLM 공급자 연동 및 비교
- 사용자별 호출 상한, 호출 로그/비용 모니터링
- 학습 일정 관리, 단계별 학습 추천 고도화 (주간 학습 목표 일수 설정은 MVP 포함, FR-4.9)
- 객관식/단답 퀴즈 모드
- 영어 등 다국어 자료 및 UI
- 네이티브 모바일 앱
- 교수자/관리자용 기능, 학습자 간 공유
- .ppt(구형 형식) 지원

## 6. 기능 요구사항

### F1. 학습자료 입력 및 분석
- FR-1.0 **프로젝트**는 사용자가 만드는 학습 주제 단위다(예: "운영체제").
  - 생성할 때 이름(필수)과 설명(선택)을 입력한다. 색은 indigo → lavender → cyan 순서로 자동 배정하고, 아이콘은 이름의 첫 글자로 표시한다.
  - 프로젝트에는 자료를 여러 개 올릴 수 있다. 개념은 자료별로 추출하며(FR-1.5), 프로젝트의 개념 목록은 소속 자료 개념의 합이다.
  - 세션은 프로젝트의 개념 하나를 선택하면 시작된다 (6.2).
- FR-1.1 사용자는 프로젝트에 PDF, PPTX 파일을 업로드할 수 있다. 한 번에 여러 파일을 선택하거나 끌어다 놓을 수 있다. (.ppt, DOC/DOCX/TXT 미지원, PNG/JPG는 MVP 이후)
- FR-1.2 업로드 제한은 **파일당 50MB, PDF 300쪽 / PPTX 300슬라이드**이다.
- FR-1.3 원본 파일은 비공개 Cloud Storage 버킷에 보관하며, 소유자 본인만 접근할 수 있다. 분석 실패 시 원본으로 재시도한다.
- FR-1.4 시스템은 파일에서 텍스트와 구조를 추출한다. 텍스트 추출이 불가능한 스캔 PDF는 지원하지 않음을 안내한다.
- FR-1.5 시스템은 자료당 핵심 개념 **5~10개**와 각 개념의 기준 설명, 채점 체크리스트(6.1①)를 생성한다. 개념 수는 자료 분량에 맞춰 LLM이 정하되 이 범위로 제한한다.
- FR-1.6 사용자는 프로젝트 상세의 개념 탭에서 프로젝트의 개념 목록(상태, 점수 포함)을 확인할 수 있다. (수정/삭제는 MVP 이후)
- FR-1.7 분석 진행 단계(추출, 개념 생성)를 표시한다. 지원하지 않는 형식, 용량/쪽수 초과, 추출 실패 시 사유를 안내하고 재시도 버튼을 제공한다.
- FR-1.8 첫 업로드 시 "자료가 외부 AI API(OpenAI)로 전송됩니다" 안내를 보여주고 동의를 받는다.

### F2. 사용자 답변 기반 이해도 판단
- FR-2.1 사용자는 개념 하나를 선택해 자기 말로 설명할 수 있다 (파인만 기법). 개념을 선택하면 세션이 시작된다 (6.2).
- FR-2.2 AI는 설명을 개념의 채점 체크리스트와 요소별로 비교하고, 전체 상태는 6.1③의 규칙으로 산출한다.
- FR-2.3 판정은 아래 4개 상태와 근거 문장(사용자 답변과 자료의 해당 부분)을 함께 제공한다.

| 상태 | 의미 |
|---|---|
| 이해 | 모든 핵심 요소를 충족 |
| 부분 이해 | 일부 핵심 요소가 누락/부분 (답변했으나 맞히지 못한 경우 포함) |
| 오개념 | 핵심 요소와 모순되는 진술 포함 |
| 미학습 | 해당 개념에 아직 답변을 제출하지 않음 |

- FR-2.4 판정이 "이해"가 아니면 AI는 빈틈을 짚는 추가 질문을 던지고, 사용자의 재답변을 반영해 판정을 갱신한다. 추가 질문은 **세션당 최대 3회**이다 (최초 설명 1회 + 재답변 최대 3회 = 판정 최대 4회).
- FR-2.5 판정마다 **이해도 점수(0~100%)**를 함께 제공한다. 점수는 상태와 마찬가지로 요소별 판정에서 코드 규칙으로 산출한다 (6.1⑥). 점수는 상태를 대신하지 않으며 상태 규칙(6.1③)은 그대로 적용한다.
- FR-2.6 세션의 첫 질문은 LLM을 호출하지 않는 고정 문구("먼저 {개념}이(가) 무엇인지 나의 말로 설명해볼까요?")다.

### F3. 개인 맞춤형 피드백 및 학습
- FR-3.1 시스템은 이미 이해한 내용보다 부족한 개념을 우선하여 피드백한다.
- FR-3.2 피드백은 (a) 맞은 부분, (b) 빠진 부분, (c) 잘못된 부분, (d) 보완 설명으로 구성한다.
- FR-3.3 피드백 공개 시점 (정답을 바로 알려주지 않는 원칙과 양립하기 위함):

| 시점 | 공개 내용 |
|---|---|
| 세션 진행 중 (각 판정 직후) | 개념 상태, 요소별 판정 결과, (a) 맞은 부분, (b) 빠진 부분(정답을 드러내지 않는 힌트 수준), 추가 질문 |
| 세션 종료 시 (6.2) | (a)~(d) 4파트 전체, 개념 상태, 핵심 보완 포인트 요약 |

- FR-3.4 시스템은 판정 결과에 기반하여 다음 학습 개념을 제안한다. 추천 개념은 취약 개념 정렬(FR-4.3)의 1순위다. 결과 화면의 추천에서는 방금 학습한 개념을 뺀 1순위를 쓴다. 추천에는 개념명, 프로젝트명, 상태, 점수, 추천 이유(상태에 따른 고정 문구)만 표시하고 예상 소요 시간이나 예상 점수 상승폭은 표시하지 않는다.
- FR-3.5 세션 완료 시 **결과 화면**을 보여준다. 구성은 다음과 같다.
  - 개념명, 학습 일시, 학습 시간(세션 시작부터 종료까지)
  - 최종 이해도 점수, 세션 안 점수 변화(첫 판정 점수 → 마지막 판정 점수)
  - 현재 개념 상태와 "이해까지 남은 핵심 요소 N개"(`충족`이 아닌 핵심 요소 수)
  - 4파트 피드백: (a) 잘 이해한 부분, (b) 보완이 필요한 부분, (c) 잘못 이해한 부분, (d) 보완 설명과 핵심 보완 포인트. "자료에서 확인되지 않음" 진술도 함께 표시한다
  - 다음 학습 추천 (FR-3.4)
- (MVP 이후) 사용자는 피드백 유용성을 평가(👍/👎)할 수 있다.

### F4. 학습 현황 및 기록 관리
- FR-4.1 로그인/회원가입은 Firebase Authentication으로 처리한다. 로그인 수단은 **이메일/비밀번호와 구글 로그인** 두 가지다.
  - 이메일 가입은 **이메일 인증이 필수**다. 인증하지 않은 계정은 로그인은 되지만 자료 업로드와 학습을 할 수 없고 인증 안내를 받는다.
  - 비밀번호 재설정 메일을 제공한다.
  - 이메일 가입은 3단계다: ① 이메일·비밀번호 입력 → ② 인증 메일 확인(링크 방식, 재발송 가능, 재발송 대기 60초) → ③ 닉네임 입력. 인증하지 않은 계정으로 로그인하면 ② 단계로 보낸다.
  - 구글로 처음 로그인하면 닉네임 입력 화면을 보여준다(구글 표시 이름을 기본값으로 채움).
  - 닉네임은 1~20자이며 설정에서 바꿀 수 있다.
  - 로그인에 성공하면 로그인 기록(시각, 브라우저/OS 요약)을 저장한다. IP는 저장하지 않는다.
  - 백엔드는 클라이언트가 보낸 Firebase ID 토큰을 검증하여 사용자를 식별한다. 토큰이 없거나 유효하지 않거나 폐기된 요청은 거부한다.
- FR-4.2 프로젝트, 학습 세션, 답변, 판정 결과를 계정별로 저장한다. 사용자는 본인 프로젝트, 자료, 기록만 접근할 수 있다.
- FR-4.3 홈 화면은 다음을 표시한다.
  - 인사와 날짜, 히어로 배너("지금 학습하기": 취약 개념 1순위로 새 세션 시작. 취약 개념이 없으면 새 프로젝트 만들기)
  - 학습 개요 (FR-4.9): 전체 이해도, 학습 개념 수, 학습 일수
  - 다음 학습 추천 카드 (FR-3.4)
  - 나의 프로젝트: 프로젝트 카드(이름, 최근 학습 개념, 프로젝트 이해도, 개념 상태 분포)와 새 프로젝트 카드
  - 취약 개념: **오개념 > 부분 이해 > 미학습** 순서. 같은 상태 안에서는 마지막 판정 시각 최신순, 미학습은 자료 업로드 최신순 → 자료 내 개념 순서로 정렬하고, 개수 제한 없이 모두 표시한다. 클릭하면 해당 개념 학습(새 세션)으로 이동한다.
  - 개념별 이해 상태 전체는 프로젝트 상세의 개념 탭에서 보여준다.
  - 앱 내 알림 배너 (FR-4.8)
- FR-4.4 이용약관과 개인정보 처리방침을 정적 페이지로 제공한다. 본인 학습용 한정, 외부 AI API 전송, 수집 항목(이메일, 닉네임, 프로필 이미지, 업로드 자료, 학습 기록, 로그인 기록(시각, 브라우저/OS))을 명시하고 로그인 화면과 설정에서 링크한다.
- FR-4.5 **학습기록**: 사이드바 메뉴(전체 프로젝트)와 프로젝트 상세의 기록 탭(해당 프로젝트)에서 답변이 1개 이상인 세션을 최신순으로 보여준다(개념명, 프로젝트명, 일시, 학습 시간, 최종 점수, 완료/중단). 항목을 누르면 상세를 연다.
  - 완료 세션: 결과 화면(FR-3.5)과 대화 전체
  - 중단 세션: 대화(질문, 답변)와 진행 중 공개 범위(FR-3.3)의 피드백만. 4파트 결과는 보여주지 않는다 (6.2)
- FR-4.6 **설정**: 변경은 즉시 자동 저장한다.
  - 계정: 프로필(닉네임, 프로필 이미지 변경. 이미지는 JPG/PNG 최대 2MB, 없으면 이니셜 아바타), 연결된 계정(로그인 수단 Google/이메일 표시만), 이메일 인증 상태
  - 로그인 및 보안: 로그인 기록(최근 10건), 모든 기기에서 로그아웃(모든 세션의 토큰을 폐기하며 현재 기기도 로그아웃된다)
  - 학습 설정: AI 질문 난이도(기본 / 깊이 있게, 기본값 기본. 추가 질문의 문체와 깊이만 바꾸며 판정 규칙, 점수, 횟수에는 영향이 없다), 학습 알림(켜기/끄기, 기본값 켜짐), 학습 목표(주 1~7일, 기본값 3일)
  - 서비스: 이용약관, 개인정보 처리방침, 회원 탈퇴
- FR-4.7 **회원 탈퇴**: 확인 모달에서 "탈퇴"를 입력하면 Firebase 계정, DB의 모든 사용자 데이터, Cloud Storage의 원본 파일과 프로필 이미지를 즉시 삭제한다. 복구할 수 없다.
- FR-4.8 **앱 내 알림**: 학습 알림이 켜져 있으면 홈 상단에 배너로 보여준다. 알림은 두 종류다. 이메일·푸시 발송은 하지 않는다.
  - 학습 목표: 이번 주 학습일 수가 목표보다 적으면 "이번 주 목표까지 N일 남았어요"
  - 복습: 오개념 또는 부분 이해 개념이 있으면 취약 개념 1순위를 복습하도록 안내
- FR-4.9 **학습 통계** (날짜는 KST, 한 주는 월~일):
  - 학습일: 판정이 1회 이상 있었던 날
  - 전체 이해도: 학습한 모든 개념의 이해도 점수 평균 (6.1⑥)
  - 학습 개념: 판정을 1회 이상 받은 개념 수, 이번 주에 처음 판정받은 개념 수
  - 학습 일수: 최근 30일의 학습일 수, 현재 연속 학습일 수(오늘 학습하지 않았으면 어제까지 이어진 일수)
  - 사이드바 주간 위젯: 이번 주 월~일 7칸에 학습일 표시, "목표 N일 중 M일"

### F5. AI 학습 엔진
- FR-5.1 자료를 청크로 분할, 임베딩하여 pgvector에 저장한다 (RAG).
- FR-5.2 답변 평가 시 관련 청크를 검색해 근거로 사용한다. 검색 범위는 개념이 속한 **프로젝트의 모든 자료**다.
- FR-5.3 MVP는 OpenAI API만 사용한다(생성과 임베딩 모두). 모델과 파라미터는 9.2를 따른다. 호출 코드는 별도 모듈로 분리하여 이후 다른 공급자로 교체할 수 있게 한다.
- FR-5.4 개념 추출과 판정 결과는 정해진 JSON 스키마로 출력하며(Structured Outputs), 검증 실패 시 재시도한다. LLM 호출 실패 시에도 재시도 후 오류를 안내한다.
- FR-5.5 자료에 없는 내용을 사실처럼 단정하지 않는다 (근거 인용, 불확실 시 "자료에서 확인되지 않음" 표시).

### 6.1 이해도 판단 로직 (F2, F5)

LLM이 "이해했는가"를 통째로 판정하지 않는다. **LLM은 요소별 판정만 하고, 전체 상태는 코드가 규칙으로 산출한다.** 같은 입력이면 같은 상태가 나오고, 판정 이유를 요소 단위로 설명할 수 있다.

**① 채점 기준 생성 (자료 분석 시)**
- 개념마다 "이해했다면 반드시 언급해야 할 요소" 3~5개를 만든다.
- 각 요소에는 중요도(**핵심 / 보조**, 2단계, 가중치 없음)와 자료 내 근거 청크 위치를 붙인다.
- 자료에서 드러나는 흔한 오개념이 있으면 0~2개를 함께 기록한다.

**② 답변 평가 (LLM 1회 호출)**
- 입력: 개념의 체크리스트, RAG로 검색한 근거 청크, **현재 세션**에서 해당 개념에 대해 학습자가 제출한 누적 답변 전체
- 출력(JSON): 요소별 판정(`충족 / 부분 / 누락 / 모순`)과 판정 근거가 된 학습자 문장, 피드백(4파트), 추가 질문 후보
- 판정은 보수적으로 한다. 의심스러우면 한 단계 낮은 판정을 준다.
- 자료 문장을 그대로 옮긴 것으로 보이는 진술은 충족으로 인정하지 않고, 자기 말로 다시 설명하도록 유도한다. 표현이 달라도 의미가 맞으면 충족으로 인정한다.

**③ 전체 상태 산출 (코드 규칙, 위에서부터 순서대로 적용)**

| 순서 | 조건 | 상태 |
|---|---|---|
| 1 | 해당 개념에 제출된 답변이 없음 | 미학습 |
| 2 | 핵심 요소 중 하나 이상이 `모순` | 오개념 |
| 3 | 모든 핵심 요소가 `충족` | 이해 |
| 4 | 그 외 (답변했으나 핵심 요소 일부가 `부분/누락`) | 부분 이해 |

- 보조 요소는 상태에 영향을 주지 않고 피드백에만 반영한다.
- **자료에 없는 내용**은 오개념으로 처리하지 않고 "자료에서 확인되지 않음"으로 표시하며, 상태 산출에서 제외한다.

**④ 추가 질문과 재판정**
- 누락/모순 요소 중 핵심 요소를 우선하여 질문하며, 정답을 직접 알려주지 않는다.
- 질문의 문체와 깊이는 사용자의 AI 질문 난이도 설정(FR-4.6)을 따른다. "깊이 있게"는 예시 요구, 다른 개념과의 관계 같은 심화 질문을 만든다.
- 세션당 최대 3회. 재답변이 오면 최신 답변만이 아니라 세션의 누적 답변 전체를 다시 평가한다.
- 이전 판정은 이력으로 보존한다.

**⑤ 출력 안정성**
- 출력은 JSON 스키마(Structured Outputs)로 검증하고 실패 시 재시도한다.
- 출력 변동을 줄이기 위해 작업별 `reasoning.effort`를 고정한다(9.2). `gpt-5.6-luna`의 temperature 지원 여부는 공식 문서에서 확인되지 않으므로 이에 의존하지 않는다.

**⑥ 이해도 점수 산출 (코드 규칙)**
- 개념 점수(판정 1회) = 핵심 요소 판정 점수의 평균 × 100, 정수로 반올림. 판정 점수는 `충족` 1, `부분` 0.5, `누락` 0, `모순` 0이다. 보조 요소와 "자료에서 확인되지 않음" 진술은 점수에서 제외한다.
- 개념의 현재 점수는 개념 상태와 같은 판정(가장 최근 세션의 마지막 판정)의 점수다. 미학습 개념은 점수가 없다("-" 표시).
- 프로젝트 이해도 = 그 프로젝트에서 학습한 개념(미학습 제외)의 현재 점수 평균. 학습한 개념이 없으면 "-".
- 전체 이해도 = 모든 프로젝트에서 학습한 개념의 현재 점수 평균.
- 세션 점수 변화 = 그 세션의 마지막 판정 점수 − 첫 판정 점수.

### 6.2 세션 규칙

- **1세션 = 1개념.** 개념을 선택하면 새 세션이 생성된다.
- 세션 상태: `진행 중` → `완료` 또는 `중단`.
- **완료**: 판정이 "이해"에 도달하거나 추가 질문 3회를 모두 사용하면 자동 종료하고 결과 화면(FR-3.5)을 보여준다.
- **중단**: 진행 중 세션에서 이탈하면 중단으로 닫는다. 평가된 답변이 하나라도 있으면 마지막 판정을 개념 상태에 반영하고, 없으면 상태를 바꾸지 않는다. 중단된 세션은 이어할 수 없고(이어하기는 MVP 이후) 종료 요약을 보여주지 않는다.
  - 이탈 감지: "학습 종료" 버튼, 앱 내 다른 화면으로 이동, 탭 닫기/새로고침 시 클라이언트가 중단을 요청한다. 요청이 누락된 세션은 같은 사용자가 새 세션을 시작하거나 홈을 조회할 때 서버가 중단 처리한다.
  - 사용자당 진행 중 세션은 하나다.
- **재학습**: 이미 학습한 개념을 다시 선택하면 새 세션을 만들고 그 세션의 답변만으로 평가한다. 이전 세션의 답변은 평가 입력에 포함하지 않는다.
- **개념 상태**는 해당 개념의 가장 최근 세션에서 마지막으로 산출된 상태다. 이전 세션과 판정은 이력으로 보존한다.

## 8. 사용자 흐름

```
로그인(Google 또는 이메일, 첫 로그인 시 닉네임 / 이메일 가입은 인증 메일 확인) → 홈
→ 프로젝트 생성 → 자료 업로드(첫 업로드 시 외부 AI 전송 동의) → 분석 진행 → 개념 목록 확인
→ 개념 선택(세션 시작) → 설명 작성 → AI 판정(상태 + 점수) + 추가 질문 → 재답변 (최대 3회)
→ 세션 완료: 결과 화면(4파트 피드백, 점수 변화, 다음 학습 추천) → 기록 저장
→ 홈(통계·취약 개념 갱신) / 학습기록(지난 세션 상세)
```

### 9.2 AI 모델과 파라미터

확인일: 2026-10-22, OpenAI 공식 문서 기준.

| 용도 | 모델 ID | 파라미터 | 비고 |
|---|---|---|---|
| 개념 추출 + 채점 기준 생성 (6.1①) | `gpt-5.6-luna` | `reasoning.effort = medium` | Structured Outputs |
| 답변 평가: 요소별 판정, 피드백, 추가 질문 (6.1②) | `gpt-5.6-luna` | `reasoning.effort = medium` | Structured Outputs, 1회 호출 |
| 임베딩 (FR-5.1) | `text-embedding-3-small` | 1536차원 | pgvector `vector(1536)`, HNSW 인덱스 가능 |

- 모델 ID와 effort는 작업별로 환경변수로 관리하여 코드 수정 없이 교체한다 (예: 판정 품질이 부족하면 `gpt-5.6-terra`로 상향).
- `gpt-5.6-luna`는 Responses API와 Chat Completions를 지원하고 Embeddings 엔드포인트는 지원하지 않는다. 그래서 임베딩은 별도 모델을 쓴다.
- 참고 가격(1M 토큰당): `gpt-5.6-luna` 입력 $0.20 / 출력 $1.20. 컨텍스트 1,050,000 토큰.

**RAG 적용 메모**: 자료 한두 개 분량은 긴 컨텍스트로도 처리 가능하지만, 자료가 누적되고 근거 검색 정확도를 높이기 위해 RAG를 유지한다. 구현 초기에 "RAG 유무" 비교 실험으로 효과를 검증할 것을 권장한다.

### 9.3 주요 데이터 엔티티 (개략)
User(Firebase UID 연결, 닉네임, 프로필 이미지 경로, 외부 AI 전송 동의 시각), UserSettings(AI 질문 난이도, 학습 알림, 주간 학습 목표), LoginEvent(시각, 브라우저/OS), Project(이름, 설명, 색), Material(프로젝트, 원본 파일 경로, 분석 상태), Chunk(embedding), Concept(기준 설명, 현재 상태, 현재 점수), ConceptElement(핵심/보조 요소, 근거 청크), Session(개념, 상태: 진행 중/완료/중단, 추가 질문 사용 횟수, 시작/종료 시각), Message(답변/질문), Assessment(개념별 상태, 점수, 시각), AssessmentElement(요소별 판정, 근거 문장), Feedback

### 9.4 RAG와 신뢰성 수치, 처리 방식

수치는 초기값이며 환경변수로 조정한다. 구현 방식은 [architecture.md](architecture.md)를 따른다.

| 항목 | 값 |
|---|---|
| 청크 크기 | 약 800토큰 (쪽/슬라이드 경계 우선 분할) |
| 청크 오버랩 | 100토큰 |
| 근거 검색 Top-k | 5 (해당 프로젝트의 자료 안에서 검색, 요소의 근거 청크는 항상 포함) |
| LLM 호출/스키마 검증 실패 재시도 | 최대 2회 (최초 포함 3회 시도), 지수 백오프 |
| 개념 추출 입력 | 청크 ID가 붙은 자료 전체를 1회 호출로 입력 |
| 답변 평가 응답 | 동기 요청 (평가 완료까지 대기, 로딩 표시) |
| 업로드 경로 | 백엔드가 발급한 Signed URL로 브라우저가 GCS에 직접 업로드 |
| API 호출 | 브라우저가 FastAPI를 직접 호출 (Bearer ID 토큰, CORS) |
